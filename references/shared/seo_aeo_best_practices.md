# SEO & AEO Best Practices - Universal Guide

Comprehensive guidelines for optimizing content for both traditional search engines AND AI overviews. Applies to all markets (Norway, France, and future expansions).

---

## Part 1: Traditional SEO Fundamentals

### Keyword Research & Targeting

**Primary keyword selection:**
- One main keyword per article
- Must have search volume (check GSC for existing impressions)
- Must match Getaround's business (avoid vanity traffic)
- Include in: H1, intro, one H2/H3, conclusion, meta description

**Secondary keywords:**
- 2-4 related keywords per article
- Natural variations and long-tail
- Weave naturally throughout body

**Keyword placement priorities:**
1. H1 (title) - MUST include main keyword
2. First 100 words - Include main keyword early
3. One H2 or H3 - Reinforce main keyword
4. Conclusion - Include main keyword
5. Meta description - Include main keyword
6. Throughout body - Natural frequency (avoid stuffing)

**Keyword density:**
- Main keyword: 0.5-2% density (natural)
- Avoid exact-match repetition - use variations
- Focus on natural language, not keyword stuffing

### Search Intent Matching

**4 types of search intent:**

| Intent | Signals | Format | CTA Strength |
|--------|---------|--------|--------------|
| Informational | "how to", "what is", "guide" | Educational guides | Soft |
| Navigational | Brand + location | Direct, concise | Direct |
| Transactional | "rent", "book", "buy" | Product-focused | Strong |
| Commercial | "best", "vs", "compare" | Comparison, reviews | Medium |

**Always match content format to search intent.**

### Title Tag (H1) Optimization

**Best practices:**
- 50-60 characters (display fully in SERP)
- Include main keyword at start or near start
- Make it compelling (not just keyword)
- Use power words appropriate to market
- Include number if listicle
- Include location if relevant

**Universal title patterns:**
- Listicle: "Top [X] [Things] in [Location]"
- Guide: "[Complete/Ultimate] Guide to [Topic]"
- How-to: "How to [Action]: [Benefit]"
- Comparison: "[A] vs [B]: [Decisive factor]"

### Meta Description Optimization

**Best practices:**
- 150-160 characters
- Include main keyword naturally
- Include compelling benefit/hook
- Include call-to-action
- Match search intent

**Meta description formula:**
[Keyword phrase] + [Key benefit] + [CTA or promise]

### Header Structure (H2/H3/H4)

**Best practices:**
- H1: One per article (the title)
- H2: Main sections (4-8 per article)
- H3: Subsections under H2 (as needed)
- H4: Rarely needed (only for deep nesting)

**Header hierarchy rules:**
- Never skip levels (H2 → H4 is wrong)
- Use descriptive headers (not just "Section 1")
- Include keywords naturally in 1-2 headers
- Make headers scannable (user should understand article from headers alone)

### Hybrid Headline Strategy (AEO-Optimized)

Balance SEO and AEO with a hybrid approach to headers:

| Level | Format | Rationale | Example |
|-------|--------|-----------|---------|
| H2 | Question | Matches search queries, featured snippets | "Hvor mye kan du tjene?" |
| H3 | Statement with data | Internal navigation, CTR optimization | "Tesla: 8 000–15 000 kr/mnd" |

**Critical rule:** First sentence after H2 = direct answer with data. Don't introduce or context-set – answer immediately.

**Why this works:**
- Questions match how people search (voice search, featured snippets)
- Statements with numbers create compelling navigation
- Direct answers improve AI citation likelihood
- Combines SEO keyword placement with AEO structure

### Internal Linking Strategy

**Why internal linking matters:**
- Helps Google understand site structure
- Distributes page authority
- Keeps users on site longer
- Improves crawlability

**Best practices:**
- 3-5 internal links per article (minimum)
- Link to related articles (same topic cluster)
- Link from high-traffic articles to lower-traffic quality content
- Use descriptive anchor text (not "click here")
- Link contextually (within body text)

### Content Length Guidelines

| Content Type | Word Count | Depth Level |
|--------------|------------|-------------|
| Listicles | 1,200-2,000 | Medium |
| Comprehensive guides | 1,800-2,500 | Deep |
| Use-case articles | 800-1,200 | Focused |
| City/destination guides | 2,000-3,000 | Comprehensive |
| Product features | 600-1,000 | Concise |

### Readability & Formatting

**Paragraph length:**
- 2-4 sentences per paragraph (mobile-friendly)
- Mix short and medium paragraphs
- Break up long sections with headers

**Sentence length:**
- 15-20 words average
- Mix short (5-10) and medium (15-25) sentences
- Avoid long, complex sentences

**Formatting elements:**
- **Bold** key terms and takeaways (sparingly)
- Use bullet lists for 3+ items
- Use numbered lists for steps or rankings
- Use blockquotes for important callouts
- Add tables for comparisons or data

**Scannable content:**
- User should understand article from headers + bold text alone
- First sentence of each section = key takeaway
- Last sentence of intro = promise

### Image Optimization

**Best practices:**
- Include 1 hero image (top of article)
- 1-2 images per major section
- Alt text with keywords (naturally)
- Descriptive file names (not "IMG_1234.jpg")
- Compressed for fast loading

## Part 2: AEO (Answer Engine Optimization)

### Understanding AEO

**What is AEO?**
AEO = Answer Engine Optimization = Optimizing content for AI overviews, LLM training data, and voice search.

**Why it matters:**
- Google SGE shows AI-generated overviews
- ChatGPT, Claude, Perplexity cite sources in responses
- Voice search uses AI to parse and answer
- Being cited in AI responses = massive visibility boost

**Key difference from SEO:**
- SEO: Optimize to rank in traditional search results (list of links)
- AEO: Optimize to be cited/featured in AI-generated answers

### E-E-A-T Signals (Critical for AEO)

**E-E-A-T = Experience, Expertise, Authoritativeness, Trustworthiness**

Google (and LLMs) use E-E-A-T to determine which sources to cite.

**How to demonstrate E-E-A-T:**

| Signal | How to Demonstrate |
|--------|-------------------|
| Experience | First-hand insights, real user data, testimonials |
| Expertise | Specific data, statistics, proper terminology |
| Authority | Author credentials, company position, citations |
| Trust | Transparency, accuracy, disclaimers, updated info |

### FAQ Schema & Structured Data

**Why FAQ schema matters:**
- Featured snippets in Google
- "People Also Ask" inclusion
- AI overview citation
- Voice search answers

**Best practices:**
- Include 3-7 FAQ questions at article end
- Answer briefly (50-100 words per answer)
- Use natural question phrasing
- Include long-tail keywords in questions
- Format properly for schema implementation

**FAQ section structure:**
```markdown
## Frequently Asked Questions / Ofte stilte spørsmål / Questions fréquentes

### [Natural question with keyword]?
[Direct answer, 50-100 words. Comprehensive but concise.]

### [Second question]?
[Answer...]
```

### Q&A Content Structure

**Beyond FAQ: Structure article sections as Q&A**

AI models prefer clear question-answer formats.

**Best practices:**
- Use H2/H3 as questions where appropriate
- Answer immediately below header (first paragraph = direct answer)
- Expand answer in subsequent paragraphs
- Include variations of same question in body text

### Unique Data Points & Statistics

**Why unique data matters:**
- LLMs prioritize sources with original data
- Increases citation likelihood
- Builds authority
- Creates "linkable" content

**What counts as unique data:**
- Proprietary Getaround booking data
- User survey results
- Pricing analysis from internal data
- Trend analysis
- Local market insights

**How to present data:**
- Lead with the number
- Include source/attribution
- Add context
- Visualize when possible (tables, lists)

### Expert Quotes & Attributions

**Why expert quotes matter:**
- Increases E-E-A-T (authority)
- LLMs prefer attributed information
- Adds credibility
- Provides diverse perspectives

**How to include:**
- Name + title/credential
- Quote + attribution
- Expert insight with context

### Content Freshness Signals

**Why freshness matters:**
- Google prioritizes recent content for time-sensitive queries
- LLMs check publication/update dates
- Users trust updated information

**How to signal freshness:**
- Include year in title (for relevant content)
- Update date in metadata
- Reference recent events/data
- Review/update content regularly
- Add "Last updated: [date]" where appropriate

### External Reference Guidelines

Different data types require different approaches to maintain accuracy and trust over time.

| Data Type | Volatility | Approach | Example |
|-----------|------------|----------|---------|
| Tax rates/rules | High | **Refer to source** - don't cite numbers | "Se Skatteetaten.no for gjeldende regler" |
| Tax thresholds | Medium | **Cite + caveat** | "Grensen er p.t. 10 000 kr (sjekk for oppdatering)" |
| Internal data | Low | **Cite directly** with ranges | "Utleiere tjener typisk 3 000–15 000 kr/mnd" |
| Insurance specifics | Medium | **Refer to page** | "Se forsikringsvilkår på getaround.com" |
| Regulatory deadlines | High | **Refer + caveat** | "ZFE-regler endres – sjekk certificat-air.gouv.fr" |

**Why this matters:**
- Volatile data ages content fast (wrong tax rates = lost trust)
- Referring to sources maintains credibility
- Internal data is safe to cite (we control updates)
- Disclaimers show awareness and professionalism

### Semantic Richness

**What is semantic richness?**
Using related terms, concepts, and entities that help AI understand topic fully.

**How to increase semantic richness:**
- Use related terms (synonyms, variations)
- Mention related entities (locations, brands, products)
- Include co-occurring concepts
- Add contextual information (why, when, who, how)

## Part 3: Getaround-Specific Integration

### USP Integration (Natural, Not Pushy)

**Core USPs to weave into content:**

| USP | Natural Integration | Avoid |
|-----|---------------------|-------|
| Proximity | "Cars available in your neighborhood..." | "We have cars everywhere!" |
| Convenience | "Book in minutes via the app..." | "So easy! So fast!" |
| Flexibility | "Whether you need a car for hours or weeks..." | "Maximum flexibility!" |
| Connect | "With Connect, unlock directly with your phone..." | "Revolutionary technology!" |
| Price | "Car-sharing is often 30-40% cheaper..." | "CHEAPEST! 40% off!" |
| Insurance | "Insurance included, with options to reduce deductible..." | "Safest ever!" |

**Golden rule:** Integrate USPs as facts/benefits, not marketing copy. Show, don't sell.

### CTA Guidelines

**CTA strength by content type:**

| Content Type | CTA Strength | Placement | Example |
|--------------|--------------|-----------|---------|
| Informational | Soft | End only | "Ready to explore? Find your car..." |
| Use-case | Medium | Middle + End | "Find the perfect [car type]..." |
| Transactional | Strong | Multiple | "Book now", "See available cars" |
| Owner content | Medium | After benefits + End | "Start earning with your car..." |

**Best practices:**
- One primary CTA per article (two max for long articles)
- Make it contextual (not generic)
- Link to relevant page (specific cars, signup, category)
- No ALL CAPS or excessive punctuation

## Part 4: Markdown Formatting for Ghost CMS

### Required Format

All articles must be output as **100% valid Markdown** ready to paste into Ghost CMS.

### Basic Markdown Elements

```markdown
# H1 - Article title (one per article)
## H2 - Main sections
### H3 - Subsections
#### H4 - Rarely needed

**Bold text** for emphasis
*Italic text* (use sparingly)

- Bullet list item 1
- Bullet list item 2

1. Numbered list item 1
2. Numbered list item 2

[Link text](https://url.com)

![Alt text](image-url)

> Blockquote for callouts

| Header 1 | Header 2 |
|----------|----------|
| Cell 1   | Cell 2   |
```

### SEO Metadata Section

At the end of every article, include:

```markdown
---

**SEO Metadata:**

**Title tag:** [50-60 character title with main keyword]
**Meta description:** [150-160 character description with main keyword and CTA]
**Slug:** [url-friendly-slug-with-main-keyword]
**Main keyword:** [primary keyword phrase]
**Secondary keywords:** [keyword 1, keyword 2, keyword 3]
**Internal links to add:**
- [Related article 1]
- [Related article 2]
- [Related article 3]
```

## Part 6: Common Mistakes to Avoid

### SEO Mistakes

| Mistake | Fix |
|---------|-----|
| Keyword stuffing | Use natural variations, 0.5-2% density |
| Irrelevant keywords (vanity traffic) | Validate business fit first |
| Too-long title tags | Keep to 50-60 characters |
| Generic meta descriptions | Include keyword + benefit + CTA |
| No internal links | Add 3-5 per article |
| Skipping header levels | Follow H1 → H2 → H3 |
| Images without alt text | Add descriptive alt text |

### AEO Mistakes

| Mistake | Fix |
|---------|-----|
| No FAQ section | Add 3-7 questions at end |
| Vague, general content | Include unique data |
| No attribution/sources | Add expert quotes, citations |
| Outdated information | Add freshness signals, update regularly |
| Poor E-E-A-T | Demonstrate expertise through specifics |

### Content Mistakes

| Mistake | Fix |
|---------|-----|
| Content-product mismatch | Validate business fit in Step 2 |
| Too commercial/pushy | Natural USP integration |
| Wrong tone for audience | Apply market-specific tone guide |
| Long paragraphs (wall of text) | 2-4 sentences per paragraph |
| Missing practical info | Add prices, parking, hours, tips |
| No clear value proposition | State promise in intro |
| Weak hook | Apply opening hook formulas |

### Market-Specific Mistakes

**Norway:**
- Using "De" instead of "du"
- Translated English expressions
- Ignoring Oslo priority

**France:**
- Mixing "tu" and "vous"
- Missing year stamps on professional content
- Ignoring French typography rules
- Surface-level regulatory content
